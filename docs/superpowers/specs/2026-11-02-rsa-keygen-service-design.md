# Спецификация: Сервис генерации ключей RSA (Task J1)

## 1. Обзор и назначение
Микросервис генерации пар ключей RSA и выпуска соответствующих сертификатов X.509 по запросу клиентов через сетевой TCP-сокет.

Сервис решает следующие задачи:
- Прием клиентских запросов на генерацию ключей по TCP с использованием мультиплексирования ввода-вывода (`java.nio.channels.Selector`).
- Генерация пар ключей RSA с длиной закрытого ключа 8192 бит в фиксированном пуле потоков (`java.security.KeyPairGenerator`).
- Выпуск и подпись сертификатов X.509 с использованием Bouncy Castle (`org.bouncycastle.cert.X509v3CertificateBuilder`).
- Дедупликация и кэширование в оперативной памяти (`ConcurrentHashMap<String, CompletableFuture<KeyCertPair>>`) для мгновенного ответа на повторные запросы и предотвращения двойной генерации при одновременных запросах с одинаковым именем.
- Неблокирующая отправка готовых пар ключей и сертификатов клиентам через очередь отправки (Outbound Queue) и `Selector`, предотвращая блокировку потоков генерации медленными клиентами.
- Реализация консольного клиента с поддержкой имитации медленного клиента (`--delay`) и аварийного завершения (`--abort`).

## 2. Архитектура системы

### 2.1. Модель потоков
- **I/O Reactor Thread (1 поток):**
  - Выполняет цикл ожидания событий в `java.nio.channels.Selector`.
  - Обрабатывает входящие соединения (`OP_ACCEPT`), регистрируя новые неблокирующие `SocketChannel` с вложением `ClientSession`.
  - Читает поток байт клиента (`OP_READ`) до обнаружения терминального нулевого байта (`\0`).
  - Проверяет кэш или отправляет задачу в очередь генерации.
  - Обрабатывает исходящую очередь (`ConcurrentLinkedQueue<OutboundTask>`), регистрирует интерес `OP_WRITE` и отправляет данные частями по мере готовности буфера сокета.
  - Закрывает соединение после полной отправки данных либо при обнаружении отключения/ошибки сокета.
- **Crypto Worker Pool (Фиксированный пул из N потоков):**
  - Размер пула конфигурируется через CLI (`--threads <n>`). По умолчанию равен числу доступных ядер процессора (`Runtime.getRuntime().availableProcessors()`).
  - Извлекает из очереди задачи генерации ключа.
  - Выполняет генерацию RSA 8192 бит и подпись X.509 сертификата.
  - Помещает результат в очередь исходящих сообщений Reactor'а и вызывает `selector.wakeup()`.
  - Потоки пула никогда не блокируются сетевыми операциями ввода-вывода.

### 2.2. Сетевой протокол (Wire Protocol)
- **Формат запроса:**
  - Текстовая строка в кодировке ASCII (имя субъекта), оканчивающаяся нулевым байтом `0x00`.
  - Максимальная допустимая длина имени: 256 байт (защита от переполнения буфера).
- **Формат ответа:**
  - Текстовый поток данных PEM:
    1. Закрытый ключ клиента в формате PKCS#8 PEM:
       ```
       -----BEGIN PRIVATE KEY-----
       <Base64 Encoded Key>
       -----END PRIVATE KEY-----
       ```
    2. Сертификат клиента в формате X.509 PEM:
       ```
       -----BEGIN CERTIFICATE-----
       <Base64 Encoded Certificate>
       -----END CERTIFICATE-----
       ```
  - По завершении записи сервер закрывает соединение (`close()`).

## 3. Криптографическая подсистема

### 3.1. Генерация ключей клиента
- Алгоритм: RSA 8192 бит (`KeyPairGenerator.getInstance("RSA")`, размер 8192).
- Генерация выполняется в рабочих потоках пула без синхронизации между потоками.

### 3.2. Центр Сертификации (CA Manager)
- Сертификат и закрытый ключ CA:
  - Пути задаются аргументами `--ca-key` и `--ca-cert`.
  - При отсутствии файлов на диске: автоматически создается новая ключевая пара CA (RSA 4096 бит) и самоподписанный X.509 корневой сертификат с расширением `BasicConstraints(isCA = true)`, сохраняются в указанные файлы.
  - При наличии: сертификат считывается с помощью `java.security.cert.CertificateFactory.getInstance("X.509")`, закрытый ключ считывается через BouncyCastle `PEMParser`.
- Issuer Name:
  - Фиксированное имя, передаваемое через `--issuer` (по умолчанию `CN=KeygenRootCA, O=KeygenService, C=RU`).

### 3.3. Выпуск клиентского сертификата
- Класс: `org.bouncycastle.cert.X509v3CertificateBuilder` (или `JcaX509v3CertificateBuilder`).
- Subject Name: `CN=<client_name>`.
- Срок действия: 1 год (Not Before: `now - 5 min`, Not After: `now + 365 days`).
- Серийный номер: случайный 159-битный `BigInteger`.
- Алгоритм подписи: `SHA256withRSA` с использованием приватного ключа CA.

## 4. Клиентское приложение (`KeygenClientMain`)
- Параметры командной строки:
  - `--host <host>` — адрес или имя хоста сервера.
  - `--port <port>` — номер порта TCP.
  - `--name <name>` — имя для генерации сертификата.
  - `--out-dir <path>` — директория для сохранения полученных файлов (по умолчанию: `.`).
  - `--delay <sec>` — задержка в секундах между отправкой запроса и чтением ответа (эмуляция медленного клиента).
  - `--abort` — флаг аварийного завершения клиента сразу после отправки запроса.
- Сохранение файлов:
  - `<out-dir>/<name>.key` — закрытый ключ в формате PEM.
  - `<out-dir>/<name>.crt` — сертификат в формате PEM.

## 5. Граничные случаи и отказоустойчивость
1. **Повторный запрос для уже обработанного имени:**
   - Мгновенная отдача из `ConcurrentHashMap` без нагрузки на пул генерации.
2. **Параллельные запросы для одного и того же имени:**
   - Потоки связываются с одним экземпляром `CompletableFuture`. Генерация ключа происходит один раз, результат отдается всем ожидающим клиентам.
3. **Медленный клиент (`--delay`):**
   - Клиент держит открытый сокет. Сетевой поток Reactor обслуживает запись по мере готовности (`OP_WRITE`), не задерживая генераторы и других клиентов.
4. **Аварийный сброс клиента (`--abort`):**
   - Reactor перехватывает `IOException` при чтении или записи, закрывает `SocketChannel`, очищает сессию. Вычисление ключа завершается и помещается в кэш.
5. **Превышение длины имени:**
   - Если нуль-байт не найден в первых 256 байтах, соединение разрывается для защиты памяти сервера.

## 6. План тестирования (JUnit 5)
1. **Тесты криптографии (`CryptoServiceTest`, `CaManagerTest`, `PemUtilsTest`):**
   - Корректность PEM сериализации и десериализации ключей и сертификатов.
   - Проверка подписи сертификата открытым ключом CA (`cert.verify(...)`).
   - Проверка совпадения Subject DN и открытого ключа сертификата.
2. **Интеграционные тесты сервера (`KeygenServerIntegrationTest`):**
   - Успешный цикл запроса и ответа клиента.
   - Дедупликация одновременных запросов с одинаковым именем.
   - Работа с медленными клиентами (не блокируют параллельные быстрые запросы).
   - Обработка аварийно завершающихся клиентов (`--abort`).
   - Стресс-тест на 100+ одновременных подключений через мультиплексирование NIO `Selector`.
